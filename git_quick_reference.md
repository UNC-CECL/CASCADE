# Git Quick Reference

A practical cheat sheet for working with git in the PyCharm/PowerShell terminal on the CASCADE project.

---

## The core workflow

Every normal work session follows the same loop:

```powershell
git status                          # see what's changed
git add <file>                      # stage specific file(s)
git add -A                          # stage everything (respects .gitignore)
git commit -m "short description"   # save a snapshot
git push                            # send it to GitHub
```

**Run `git status` often.** It's free, changes nothing, and tells you exactly what's staged, what's modified, and what's untracked. When in doubt, check status before you commit.

---

## When to commit

Commit whenever you reach a working checkpoint — not just at the end of the day. Good moments to commit:

- You finished a function/script and it runs without errors
- You fixed a bug
- You're about to try something risky and want a safe point to return to
- You're wrapping up for the day

Small, frequent commits are easier to understand later (and easier to undo) than one giant commit with a week of changes crammed in.

**Don't commit:**
- Code that doesn't run at all (unless you're deliberately saving a work-in-progress — say so in the message)
- Large data/output files — check `.gitignore` is catching these before you `git add -A`

---

## Writing commit messages

Format: short summary in **present tense**, like you're giving an instruction.

```
Add dune topo extraction for 2009 domains
Fix off-by-one error in storm window indexing
Update road setback CSVs for 1984 hindcast
```

Not:
```
fixed stuff
updates
asdf
```

If you need more detail, add a blank line then a longer explanation:
```powershell
git commit -m "Fix storm window bug" -m "Window was using inclusive end index, causing overlap between periods."
```

Rule of thumb: someone (including future-you) should be able to read `git log --oneline` and understand what happened without opening any files.

## Checking history

Reach for these when you're not sure what you already did, or want to double-check what you're about to commit.

```powershell
git log --oneline           # "what have I done recently?" — compact, one line per commit
git log                     # same, but with full dates and messages
git diff                    # "what did I just change?" — line-by-line, before staging
git diff --staged           # "what's about to be committed?" — line-by-line, after staging
```

## Branches

```powershell
git branch                          # list local branches, * marks current
git checkout <branch-name>          # switch branches
git checkout -b <new-branch-name>   # create AND switch to a new branch
git push origin <branch-name>       # push a branch to GitHub for the first time
```

Use a new branch when starting a distinct chunk of work (a new analysis, a risky refactor) so your main working branch stays stable.

## .gitignore reminders

- `.gitignore` only stops **future** tracking — it won't remove files already committed
- After editing `.gitignore`, re-sync what's staged with:
  ```powershell
  git rm -r --cached .
  git add -A
  git status
  ```
  then review the status output before committing
- Common things to exclude on this project: `*.npy`, `*.npz`, `*.tif`, `*.png`, `*.gif`, raw data/cache folders, anything auto-generated by a script run

## Troubleshooting

**Push fails with a large file / size limit error:**
1. Check the file size named in the error
2. Add that file/pattern to `.gitignore`
3. Unstage just that file: `git rm --cached <path>`
4. Fold the fix into your last commit (only if not yet pushed anywhere): `git commit --amend --no-edit`
5. Push again

**Push fails with an authentication error** (`Invalid username or token`, `password authentication not supported`):
1. Open Windows Credential Manager, remove any `git:https://github.com` entries
2. Push again — a browser window should prompt a fresh login

**Other common symptoms:**

| Symptom | Likely cause | Fix |
|---|---|---|
| `fatal: not a git repository` | You're in the wrong folder | `cd` into the actual project folder (should contain `.git`) |
| `git status` shows unexpected files | `.gitignore` pattern too broad or too narrow | Re-read the pattern carefully; re-run reset/re-add cycle |
| Files still tracked after adding to `.gitignore` | They were already committed before the ignore rule existed | `git rm --cached <path>`, then commit |

---

## Golden rules

1. `git status` before you `add`, and again before you `commit`.
2. Commit often, in small logical chunks, with messages that explain *what* and briefly *why*.
3. Never `git add -A` blindly right after a big `.gitignore` change — check `git status` first.
4. If a push fails, read the actual error message carefully before trying a fix — it usually tells you exactly what's wrong.
