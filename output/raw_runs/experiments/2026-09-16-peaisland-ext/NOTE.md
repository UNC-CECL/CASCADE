# 2026-09-16-peaisland-ext

**Question.** Does the orientation of the buffer beyond the modelled reach
change the hindcast? The matrix models GIS 1-90 and pads each end with 15
invented domains that extrapolate the local shoreline slope; edgeBE then
pins GIS 1 and 90 with boundary source/sink terms (+32.2 and +10.0 m/yr in
1996-2010) that take up whatever the buffer gets wrong. Here the buffer
carries the REAL coast instead: Pea Island north to GIS 115 (`n115`), on
the shared buffer topography, numbered by Hannah's whole-island domain
polygons (`1-barrier3d-domains/domain-geojson/`) exactly as the surveyed
reach was, with the ends re-solved at the new ends against CoastSat. Both
offset modes, `asrun` (the compressed planform every calibrated run uses)
and `detrended` (full strength). 1996-2010, full_management, no groin,
relocations off, Hs 2.5. Hannah, 2026-09-16.

Two things were tried and removed the same evening: a one-domain southern
extension (GIS 0; no domain polygon lies south of GIS 1) and a numbering of
the extension by northing bin, which placed 4 dune-line and 40 CoastSat
transects one domain off once the polygons existed. Their inputs and runs
were deleted; the index ledger (`retired_runs.csv`) records the runs.

**Layout.** One folder per member, `<geometry>-<mode>`:

```
<member>/1996_2010/zeroBE/<run>/     stage 0: no boundary term anywhere
<member>/step<k>/1996_2010/edgeBE/   the k-th Newton probe of the end solve
<member>/SOLVED                      names the step that stands as the solved run
logs/<member>/                       one log per run
figures/  RESULTS.md  FINDINGS.md    the answer
```

`base-detrended` is the 90-domain baseline for the detrended pairs, solved
the same way, because no calibrated detrended run exists. `base-check` is
the base geometry, compressed, edgeBE, run through the geometry-aware
runner: it must reproduce the matrix row exactly, and did. Start with
`figures/compare_main_vs_extension_gis1_90.png`: the main approach against
the solved extension on the surveyed reach.

**Inputs built for this.** `2-brie-offset/1996/ext/<geometry>/` (offsets;
GIS 1-90 identical to v2, checked), `2-brie-offset/raw_offsets/ext/` and
`transects/transects_100m_ext.csv` (the transects beyond GIS 1-90, numbered
on the continued grid), `5-scr/coastsat_lrr/1996_2010/ext/` and
`5-scr/transect_domains/transect_domain_lookup_ext.csv` (CoastSat rates
for the extension). Driver: `scripts/hatteras_ms/experiments/HAT_peaisland_extension.py`.

**Scoring.** `rmse_interior_m_yr` in the index is GIS 2-89 against the
SURVEYED CoastSat target in every geometry, so every run here is graded on
the same domains as its matrix baseline. `rmse_reach_interior_m_yr` is the
extended reach's own interior.

**Answer lives in.** `FINDINGS.md` (the reading), `RESULTS.md` (the tables,
regenerated by the driver's `score`) and `figures/` beside this file. In
one line: the buffer's orientation is not a lever. Moving the north end to
GIS 115 removes the footprint of the GIS 90 boundary term from GIS 80-90
(interior RMSE 1.098 vs 1.141) but the term itself grows (+41.7 vs +10.0 m/yr),
because it supplies observed accretion the model cannot produce, not the
buffer's shape. At full planform strength every run sits near RMSE 9.

**Runs deletable?** Once RESULTS.md is written, yes: each is re-runnable in
minutes from the driver, and its numbers are in the index.
